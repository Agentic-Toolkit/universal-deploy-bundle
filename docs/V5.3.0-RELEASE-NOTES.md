## 🛡️ How It Works

### Pre-Commit Gate
```
Developer makes changes → Attempts commit
                          ↓
                    V5.3 Pre-Commit Hook
                          ↓
                ┌─────────────────────┐
                │ 1. Code Scanner      │ ← Detects credentials, build errors
                └─────────────────────┘
                          ↓
                ┌─────────────────────┐
                │ 2. Integrity Verify  │ ← Checks SHA-256 hashes
                └─────────────────────┘
                          ↓
              If either fails → Commit blocked
              If both pass → Commit allowed ✅
```

### Integrity Verification Flow
```
Generate Manifest:
1. Calculate SHA-256 hash for every file
2. Create .integrity.json manifest
3. Calculate manifest hash
4. Save to .integrity/history/

Verify Integrity:
1. Load .integrity.json manifest
2. Recalculate hashes for all files
3. Compare with expected hashes
4. Detect corruption patterns
5. Generate developer handoff
6. Block deployment if corruption found
```

### Corruption Pattern Detection
- **Injection Detection** - Identifies `<script>`, `eval()`, `javascript:` patterns
- **Truncation Detection** - Detects partially transferred files
- **Encoding Issues** - Identifies UTF-8/corrupted character problems
- **Whitespace/Line Ending** - Detects formatting inconsistencies
- **Unknown Patterns** - Flags any unexpected changes

```bash
# Start project - generate baseline integrity
npm run integrity:generate

# Make changes...

# Commit - automatic verification
git add .
```

### 2. Pre-Deployment Verification
```bash
# Before deployment - verify all files
npm run integrity:verify

# If passed - proceed with deployment
npm run deploy:full

# If failed - review handoff
cat .integrity/handoff.json
```

### 3. Corruption Investigation
```bash
# Integrity check fails - view report
npm run integrity:report

# Check corruption details
cat .integrity/handoff.json

# Restore from last known good
git checkout $(cat .integrity/last-good.json | jq -r '.identifier') -- <file>

# Re-verify
npm run integrity:verify
```

### 4. Enterprise Security
```bash
# Use SHA-512 for high-security projects
npm run integrity:generate --sha-512

# Verify with SHA-512
npm run integrity:verify --sha-512
```

## 🐛 What to Do When Verification Fails

### 1. Check the Report
```bash
npm run integrity:report
```

### 2. Review Handoff
```bash
cat .integrity/handoff.json
```

### 3. Identify Corruption Pattern
The handoff will show:
- Injection attacks (CRITICAL)
- Truncated files (HIGH)
- Encoding issues (MEDIUM)
- Unknown patterns (MEDIUM)
- Whitespace/line endings (LOW)

### 4. Restore or Fix
```bash
# Option A: Restore from last known good
git checkout $(cat .integrity/last-good.json | jq -r '.identifier') -- <file>

# Option B: Fix file manually (if changes are intentional)
# Edit the file
# Regenerate manifest: npm run integrity:generate --force
```

### 5. Re-verify
```bash
npm run integrity:verify
```

### 6. Only Proceed When Verified
```bash
# Now safe to deploy
npm run deploy:full
```

## 🆘 Troubleshooting

### Issue: Verification fails but no changes made
**Solution:**
```bash
# Check line endings
git config core.autocrlf false

# Regenerate manifest
npm run integrity:generate
```

### Issue: Manifest too large
**Solution:**
```bash
# Clean old history
npm run integrity:clean 10

# Exclude more patterns in IntegrityManifest.js
```

### Issue: Verification slow
**Solution:**
```bash
# Use verbose mode to see progress
npm run integrity:verify --verbose

# Check for large files being hashed
npm run integrity:report
```
